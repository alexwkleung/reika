# Architecture and caveats

[← README](../README.md)

The big ideas:

- **Bootstrap once.** `bundle.cwd`, `bundle.repoMap`, `bundle.fileIndex`, AGENTS.md, project summary are all built once at startup and kept stable across turns. Critical for prompt caching at the provider.
- **Repo map.** One line per source file naming its definitions (`path: sym, sym, …`), ranked so the files the rest of the repo reaches for fit first in the `REIKA_REPO_MAP_BUDGET`. Regex-per-language, no parser: TS/JS (exports), Python, Go, Rust, Java/C#, Kotlin, Swift, C/C++/Objective-C, Ruby, PHP, Lua, shell. A language is one entry in `LANGUAGES` (`src/context/repomap.ts`).
- **Payload aging.** Tool results carry `summary` + `payload`. Only the latest contiguous block of tool results sends `payload` to the model; older ones collapse to `summary`-only. Keeps history token-bounded without losing information the model just acted on.
- **Single system-prompt builder.** Parameterized; no duplication across modes.
- **OpenAI-compatible end-to-end.** Local inference engines and cloud providers all work.
- **Streaming, abort, approval, subagent** all flow through one `AbortController` and one set of callbacks.

## Working caveats

- Approvals default to `safe`: ordinary edits/commands auto-run, but commands matching a dangerous pattern (`rm -rf`, `rm -f`, force push, `git reset --hard`/`checkout --`/`stash drop`, any package install/uninstall, `npx`, `curl`/`wget`, `pkill`/`killall`, etc.) and writes outside the project still force a manual approve/reject — yolo mode with safeguards, and everything it lets through is recoverable from git. `/approvals off` (or `REIKA_AUTO_APPROVE=off`) confirms every action instead. For true no-prompts-ever, set `REIKA_AUTO_APPROVE=bypass` (or `yolo`) — that runs dangerous commands without asking.
- Subagent quality depends on the model, and what a subagent buys is **context**, not speed: its reads land in the main context as one report instead of N payloads, at the cost of the server re-prefilling the parent's context when the subagent returns (one slot). A subagent always returns something — its last budgeted round is a forced report — and the report ends with a note naming any file the task listed that it never read, so the parent can hand the remainder to a second subagent (at most 3 dispatching rounds per turn, up to 4 subagents per round) instead of reading it itself. An aged report keeps its head — the chain — rather than collapsing to a byte count.
- The repo map and file index don't auto-refresh after external file changes — `/cd .` re-indexes.
- Startup crawls are bounded, breadth-first: the repo map reads at most 3,000 source files across 4,000 directories, the file index keeps 10,000 paths, and nested `.gitignore` discovery stops at 2,000 directories. A tree past those caps (a home directory, a monorepo) starts in about a second with a shallow-first map rather than a complete one; run Reika from the project root for full coverage.
- Cmd+←/→ on macOS depends on terminal config; Ctrl+A/E always works.
- Image paste (ctrl-v) runs the image through the OS text recognizer, so it works with any model — including text-only ones. It needs `@napi-rs/system-ocr`, which ships prebuilt binaries for macOS and Windows only; on Linux the paste reports that OCR is unavailable rather than failing. It extracts _text_, so a screenshot of a stack trace or an error dialog works well and a screenshot of a UI mockup does not. Set `REIKA_VISION_MODEL` to route images through a vision model instead: it describes the image (text transcribed first, then what's shown) and the description is attached the same way, so the main model still never sees pixels and a UI mockup becomes usable. `REIKA_VISION_BASE_URL`/`_API_KEY` fall back to the main server.
- If the model itself can see, set `REIKA_VISION=native` and skip the reading step entirely: the pasted bytes are sent to the model as an OpenAI multimodal image part, for the turn they were pasted in. It's per-profile as well (`REIKA_<NAME>_VISION`), so a local text-only default can stay on `describe` while `/model <vl>` switches the session over to native and back. The image is sent once — history keeps a short "not transcribed" note where the description would go, so the model can ask you to re-paste but cannot look again later. Two things to know: `@file.png` mentions still go through the reader (only the clipboard path carries bytes), and image tokens are invisible to the context budget, so each one is charged a fixed allowance when the prompt is sized.
- Tool calling is most reliable when the model is served with its **native function-calling chat template**. Without one, models fall back to emitting tool calls as text — Reika parses the common dialects (`<tool_call>{json}</tool_call>`, Hermes `<function=…>`, pythonic `fn(k=v)`, and calls leaked into the reasoning channel) as a best-effort fallback, but the native path avoids the malformed/looping/leaked calls those fallbacks exist to catch. If a local model misbehaves on tool use, first check that your server (llama.cpp / Ollama / vLLM / MLX) loads a tools-enabled template for it.
